# 机器人项目演示视频 · 拍摄与剪辑 SOP（单机位 + 终端叠加 · 最简版）

> 形态：手机实拍真机 + 终端录屏（SSH 控制与反馈）→ 音频脉冲对齐 → 剪辑叠加同步展示。
> 打法定性：单机位、零额外工具链；数据与画面强制同源，可溯源到日志行。
> 适用项目：003 Tesseract 双臂运控 · 004 Isaac RL 到位控制。

---

## 1. 素材构成

| 层 | 来源 | 作用 |
|----|------|------|
| 主画面 | 手机实拍真机 | 唯一展示真实运控效果 |
| 实时日志 | 终端窗口录屏 | 发目标 → 动作 → 反馈的因果闭环，可信度核心 |
| 同步信号 | beep 音频 | 两路共用对齐基准（画面类标志手机收不到，不可用） |

**红线：两路素材必须来自同一次 run**，禁止拿 A run 的日志配 B run 的画面。

---

## 2. 拍摄要点（分项目）

> 本节含各项目拍摄镜头重点 + **终端日志打印规格**（可直接交开发 agent 照此改造）。

### 项目 1（传统栈 · 003 Tesseract）——重点：求解 → 规划 → 执行全流程 + 动态追踪精度

| 镜头 | 拍什么（手机）+ 叠什么（终端） | 对应卖点 |
|------|------------------------------|---------|
| ① 动态目标伺服追踪 | 目标持续移动（手移卡/滑台），臂实时跟随；终端常驻 `[SERVO] 200Hz err 0.6mm` | 200Hz 视觉伺服 + 稳态精度 |
| ② 大范围无自碰移动 | 极限位姿 A→B，**一次连录不剪辑**；终端叠 `[PLAN] ok 0.21s path 0.61m` | 规划 + 碰撞检测真实在跑；数据卡对比 `1.75s → 0.21s（5×）` |
| ③ 加分：失败→自动重规划 | 构造一个规划失败场景，终端打出失败原因 + 重规划成功 | 工程完整性（恢复机制） |

- 避免：静态摆 pose；把 RViz 当主画面（PPT 感）

**终端必须呈现的要素（日志打印规格 · 可直接交开发）**

| # | 要素 | 打印内容（示例） | 时机 |
|---|------|----------------|------|
| 1 | 全流程自动计时 | `[TIME] ik 1.2ms · plan 0.21s · exec 12.1s · total 12.3s`——程序内打点（**禁用外挂 `time` 命令**） | 到位后自动 |
| 2 | 目标 vs 当前位姿误差 | `[ERR ] pos 0.6mm  ori 0.3°`（固定单位 mm / °） | 执行中 ≥1Hz + 到位终值 |
| 3 | 求解（IK） | `[IK  ] ok 1.2ms`（耗时 + 成功/失败） | 每次求解 |
| 4 | 规划（OMPL） | `[PLAN] ok 0.21s  path 0.61m`（耗时 + 结果 + 路径长度） | 每次规划 |
| 5 | 执行（伺服） | `[SERVO] 200Hz  err mean 0.6mm  max 1.4mm`（频率 + 误差统计） | 执行结束 |
| 6 | 量化汇总 | `[SUMMARY] N=…  成功率…  err mean…  max…` | run / 批次结束 |

### 项目 2（RL · 004 Isaac RL）——重点：端到端闭环 + 成功率可复现

| 镜头 | 拍什么（手机/录屏）+ 叠什么（终端） | 对应卖点 |
|------|-----------------------------------|---------|
| ① 随机目标连续到达（核心） | **一次连录 5–10 个随机目标不剪辑**；终端计数器 `#N/10` + 每次 `sent→reached Δt` + `✓ hit` | 90.9% 到位率最直接证据；判定口径（<3cm & <5°）打角标 |
| ② 抗扰恢复 | 侧向/顶部推力后自动回到目标（注意安全、动作拍清楚）；终端标记扰动时刻 + 恢复耗时 | 域随机化带来的鲁棒性 |
| ③ 训练闭环证据（录屏，非实拍） | Isaac Lab 4096 并行环境画面 + 奖励曲线爬升（真实日志导出）+ ONNX 导出终端 | 不是手搓脚本，是完整训练→部署链 |
| ④ 加分：sim2real 对照 | 上：仿真回放同目标 / 下：真机执行，按 beep 对齐两路 | 训练与部署共用同一契约 |
| ⑤ 加分：失败案例 | 不可达目标/超限扰动 + 字幕解释策略边界 | 懂边界比全过更有说服力 |

- 避免：只拍成功集锦、没有连续一次过的 run（连续 run 正是可信度所在）

**终端必须呈现的要素（日志打印规格 · 可直接交开发）**

| # | 要素 | 打印内容（示例） | 时机 |
|---|------|----------------|------|
| 1 | 推理→执行全流程自动计时 | `[TIME] infer 1.4ms/frame · exec 1.84s · total 1.84s`——自动打点（sent → reached） | 到位后自动 |
| 2 | 目标 vs 当前位姿误差 | `[ERR ] pos 8mm  ori 2.1°`（固定单位 mm / °） | 执行中 ≥1Hz + 到位终值 |
| 3 | 推理与下发 | `[INFER] best.onnx  1.4ms/frame  50Hz`（策略文件 + 单次推理耗时 + 下发频率） | run 开始 + 周期抽打 |
| 4 | 到位判定 | `✓ hit (3/3 拍)`（位置 <3cm 且姿态 <5°） | 到位时 |
| 5 | 抗扰恢复 | `[DIST ] 受扰 → 复位 0.42s`（仅扰动镜头） | 扰动事件后 |
| 6 | 量化汇总 | `[SUMMARY] N=100  92/100 (92%)  mean 1.9s  σ0.4s` | 批次结束 |

**打印纪律（两项目通用）**：仅上表字段入日志——关闭 topic 刷屏与 debug 输出；单位固定 mm / ° / ms / s / Hz；列对齐、关键数字走高亮色 → 直接可叠屏。

### 两片共用底线

1. **各留 1 个失败/恢复镜头**——主动构造，别等偶然
2. **汇总行必须进片**（`[SUMMARY] N=… 成功率…` 停留 ≥3s），数据卡口径标 N 与判定条件
3. **叙事呼应**：两片结尾统一收一句「同一任务（到位/到达）的两种实现」——规划+伺服 vs 端到端 50Hz，合起来才是完整的「传统 → 学习」弧线

## 3. 拍摄前准备

### 终端（为镜头设计输出）
- 字号 ≥20pt（1080p 下占屏高 4%+）、宽度 ≤100 列、深色主题、关键数字 ANSI 高亮（站点橙 `#FF9100`）
- 每个 run 输出 **5–6 行**，含：目标行 + 全流程计时 + 位姿误差 + 汇总行（字段见第 2 节规格）
- 日志**随动作节奏输出**（`reached` 在到位那一刻才打印，不许提前刷完）
- 清理敏感信息：IP、密码、绝对路径、他人信息

示例（项目 1 规划 + 伺服）：
```
$ ros2 run arm_demo track --speed 0.10
[TGT  ] #01  target pos(0.52,-0.18,0.31)  ori(0°,15°,0°)
[IK   ] ok  1.2ms
[PLAN ] ok  0.21s  path 0.61m
[SERVO] 200Hz  err pos 0.6mm  ori 0.3°  (max 1.4mm)
[DONE ] 3/3 到达   [TIME] ik 1.2ms · plan 0.21s · exec 12.1s · total 12.3s
[SUMMARY] N=20  追踪成功率 100%  err mean 0.6mm  max 1.4mm
```

示例（项目 2 RL 到位）：
```
$ ros2 run rl_deploy reaching --policy best.onnx
[RUN 042] best.onnx  50Hz  (infer 1.4ms/frame)
[TGT  ] #07  pos(0.42,-0.18,0.55)  ori(0°,15°,0°)
[ERR  ] pos 8mm  ori 2.1°  → ✓ hit (3/3 拍)   Δt 1.84s
[SUMMARY] N=100  92/100 (92%)  mean 1.9s  σ0.4s
```

### 录屏（OBS）
- 只捕获**终端窗口**（1280×720 或 1920×1080），不录整个桌面
- 恒定帧率；**开音频采集**（beep 必须进录屏音轨）
- 帧率与手机一致（推荐双双 60fps）

### 手机
- 横屏 1080p 恒定帧率、三脚架/稳定支撑、镜头尽量垂直运动平面
- **锁定曝光 / 白平衡 / 对焦**；开勿扰模式（防来电打断）
- 背景干净（纯色墙 / 深色布），白天窗光或柔光台灯

### 日志与台账
- 视频之外留存 raw log（重定向 / `script` / tmux 日志）
- 建表：`run_id | 日期 | 镜头号 | take | 指标 | 数值 | 日志路径`

## 4. 拍摄 SOP（每个 run 照做）

```
1. 手机开录，先静置 2~3 秒（留对齐余量）
2. 终端执行：beep 一声 + 打印 "=== SYNC t=0 ==="     ← 首同步点
3. 正常执行 run（发目标 → 动作 → 反馈）
4. 结束：beep 两声                                  ← 尾同步点（校验漂移）
5. 停止两边录制，立刻回填台账
```
- beep 约定：**首 1 声 / 尾 2 声**，剪辑时秒识别
- 每个镜头录 3–5 条，挑最稳的一条
- 失败/恢复镜头主动构造（规划失败重规划、超限扰动），至少每片保留 1 个

## 5. 对齐与校验（三重确认）

| # | 手段 | 精度 / 判据 |
|---|------|------------|
| 1 | 音频波形对齐（两路 beep 尖峰拖到同点） | ≤1 帧（16–33ms） |
| 2 | 录屏画面里 `=== SYNC t=0 ===` 与 beep 同帧 | 目视确认 |
| 3 | 手机画面「机器启动第一帧」↔ 日志 `sent` 时间戳 | 误差 ≤0.3s |
| 4 | 首尾两 beep 间距在两条时间线上一致 | 差值 >2 帧 → 对录屏轻微变速补偿 |

## 6. 剪辑合成规范

| 段落 | 手机画面 | 终端层 |
|------|---------|--------|
| 钩子 0–10s | 全屏 | 右下小窗 25%（常驻误差数字） |
| 连续演示 | 上 60–65% | 下 35–40% 日志跟随 |
| 数据段 | 缩小或隐藏 | 终端全屏 + 汇总行放大 2 倍 |

- 录屏层：8px 圆角 + 1px 描边，站点深色底 `#232323`
- 视觉统一：站点色系（橙 `#FF9100` 只用于强调数字/高亮）+ Geist / Geist Mono；数字一律 Mono
- 节奏：切镜 3–5s；关键数字放大 1.5s 高亮；数据卡停留 ≥3s
- 字幕：全片硬字幕（招聘方常静音观看），关键词大字
- 音频：BGM −18~−24 LUFS；音效只在「到位/成功」点缀
- 片头即钩子（不加片头动画）；片尾 3s：项目名 + GitHub

- [ ] 每个 run 终端有：run id + 时间戳 + 结果行

- [ ] beep 对齐可用，偏移 ≤1 帧
- [ ] 「机器启动帧 ↔ sent 时间戳」目视一致（≤0.3s）
- [ ] raw log 已存档，随机抽 10 个 run 可回指
- [ ] 至少 1 个失败/恢复镜头
- [ ] 简历每个数字都能回指到某一行日志

## 9. 常见坑

- 两路帧率不一致还混剪 → 抽帧抖动；两路与剪辑工程同帧率
- beep 贴着视频开头 → 波形难找；执行前留 2–3 秒静置
- 录屏弹出通知/微信 → 开勿扰 + 只录终端窗口
- OBS 未开音频采集 → beep 只有手机侧有，对齐退化回目测
- 日志提前刷完 / 与动作脱节 → `reached` 必须到位才打印
- 拿不同 run 的日志配画面 → 直接失信，红线禁止
