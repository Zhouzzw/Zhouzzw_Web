- 起服务：`npm run dev`（5173 常被占用，会自动跳 5174，读日志里的实际端口）；**动手前先 `curl` 一次确认端口**——本轮若端口猜错，所有探针都会静默测到别的服务
- 截图 / 测量探针：本轮已重建并留在 **`/tmp/probe/`**（在仓库外，不会污染 git）：`cdp.mjs`（截屏 / 定点 / eval）、`breakpoint.js`（断点指标）、`roles.js`、`interact.mjs`（交互 + Tab + 无障碍）、`contrast.js`（逐条对比度）、`perf.js` / `perf2.mjs`（体积 / LCP / CLS）。用法：`node cdp.mjs eval --w 1440 --h 900 --port 9901 --file xxx.js`（**端口必须每档唯一，且别写成 `9$w` 这种会超过 65535 的拼法**）
- 参考站**无需重抓**；复抓方式：`web_fetch` + 指定 `fetchInfo`（比 anysearch extract 省 token）
- 探针踩坑：`--virtual-time-budget` 会跳过平滑滚动与 rAF；hero `min-height:100svh` 会被超大 `--window-size` 撑坏 → 用 CDP `captureBeyondViewport` 分段截（每段 ≤8000px）；`#projects` 这类锚点跳转要用 `Runtime.evaluate` 触发放平滑滚动后再读 `scrollY`
- **对比度测量的时序坑**：hero 的 kicker/title/CTA 用的是 `animation: fadeUp … forwards`（起始 `opacity: 0`、延迟 0.1–0.35s）。**页面加载后必须等 ≥2.5s 再读 computed style**，否则会把「动画尚未开始」读成 `opacity: 0`，进而误判成「内容不可见 / 对比度 1:1」。本轮第一版对比度脚本就踩了这个坑（`.cta-split__left`、`.cta-split__right` 被误报为 1:1），第二版加了等待与 `<2.5s 剔除` 才得到可信结果。注意 `.animate-on-scroll`（`desktop.css:513`）本身已是 `opacity: 1; transform: none`，与 A2 一致，不是坑源
